## 1. 输入格式（`inputs/*.txt`，stdin 逐行读取）

头部（顺序固定）：

```text
COLORS <chars>      普通球颜色集合，如 COLORS RGBY（大写字母，2~8 个，无空格无重复）
TRACK <chars>       初始轨道，从左到右，如 TRACK RRBB（只含 COLORS 内字母）
QUEUE <chars>       待发射队列，队首在最左，如 QUEUE BRB（可含特殊球 * 与 ?）
LIMIT <n>           可选：操作步数上限（正整数）。缺省 = 不限
```

- `TRACK` 可为空串（`TRACK` 后无字符）：轨道初始为空。
- `QUEUE` 可为空串：装载后立即按胜负规则判局（轨道空 = 胜）。

指令（头部之后，每行一条，前导/尾随空白忽略；**指令名不区分大小写**，
回显保留输入原文；参数中的颜色仍须为大写字母）：

| 指令 | 语法 | 语义 |
| --- | --- | --- |
| 发射 | `SHOOT <pos>` | 取队首球插入轨道，插入后新球位于下标 `pos` |
| 发射（变色球） | `SHOOT <pos> <color>` | 同上；`color` 为一个 COLORS 内字母。**仅当队首为 `?` 时允许且必须携带** |
| 撤销 | `UNDO` | 撤销最近一步可撤销操作（含消除回滚、分数/步数回滚） |
| 交换 | `SWAP` | 交换待发射队列前两球 |
| 提示 | `HINT` | 输出当前队首球的最优插入位置（不改变任何状态，不计步数） |
| 倒退 | `REVERSE <i> <j>` | 就地反转轨道闭区间 `[i, j]`（0-based，i ≤ j），反转后检查消除 |
| 帮助 | `HELP` | 输出指令帮助（v1.1；元指令，不改状态、不计步数，终局后仍可用） |
| 退出 | `QUIT` | 立即结束，按当前状态输出终局 |

### 位置与区间语义

- 下标 **0-based**，从轨道**左端**起。
- `SHOOT p`：插入后新球位于下标 `p`，即插到当前下标 `p` 的球**之前**；`p ∈ [0, n]`，`p = n` 为尾插。
- `REVERSE i j`：闭区间 `[i, j]`，`0 ≤ i ≤ j < n`。

## 2. 球符号

| 符号 | 名称 | 出现位置 | 语义 |
| --- | --- | --- | --- |
| `A-Z`（COLORS 声明） | 普通球 | 轨道、队列 | 三连同色消除 |
| `*` | 炸弹球 | 仅队列 | 发射后消除以炸弹为中心的至多 3 连球（无视颜色，先右后左扩展，两侧不足时消到端点，至少消炸弹自身）；后续连锁按普通规则 |
| `?` | 变色球 | 仅队列 | `SHOOT` 时必须携带 `<color>`，落位瞬间定色，之后按普通球参与消除 |

`*` 与 `?` 出现在 `TRACK` 行为**非法输入**（驱动报错）。`HINT` 对 `?` 队首返回不可提示（见 §5）。

## 3. 输出格式（stdout，`outputs/*.txt` 同构）

### 3.1 头部回显

```text
COLORS RGBY
TRACK RRBB
QUEUE BRB
LIMIT 5            ← 仅输入含 LIMIT 时回显
READY
```

### 3.2 每条指令的输出

**SHOOT**（含消除事件，按轮次逐条）：

```text
<原指令行>                  回显指令（按输入原样回显；变色球必须携带颜色，
                            因此回显行含 <color>，普通球不带颜色参数）
ELIM round=<r> left=<l> count=<c> balls=<b> score=+<p>
TRACK <当前轨道>             每轮消除后各输出一次
...                         每轮消除一条（round 从 1 起，连锁递增）
QUEUE <当前队列>             发射后输出一次（消除不改变队列）
```

无消除时：`ELIM` 全部省略，但 `TRACK` 与 `QUEUE` 仍各输出一条（终态轨道/队列）。

`left` 为本轮消除段在**本轮消除前**轨道中的左下标（与撤销记录同坐标系）。

**UNDO**：

```text
UNDO
TRACK <轨道>
QUEUE <队列>
```

（无可撤销时输出 `UNDO` + `ERROR 撤销栈为空`，游戏继续。）

**SWAP**：

```text
SWAP
QUEUE <队列>
```

**HINT**（不改状态、不计步数；**HINT 行即结果行**——回显与结果合并，无独立的指令回显行）：

```text
HINT <pos>                  有最优位时
HINT -1                     无可消除位/队首为变色球时
```

**HELP**（v1.1；不改状态、不计步数；正文固定，逐字节可比对）：

```text
HELP
可用指令：
  SHOOT <pos> [color]     发射队首球到下标 pos（0 起，p=n 为尾插）
  UNDO                    撤销上一步（含连锁回滚，可撤销终局步）
  SWAP                    交换待发射队列的头两球
  HINT                    提示队首球的最优插入位置（-1 = 无可消除位）
  REVERSE <i> <j>         反转轨道闭区间 [i, j]（0 <= i <= j < n）
  HELP                    显示本帮助（不计步数）
  QUIT                    退出并输出终局
特殊球：* 炸弹（消除邻域至多 3 球）  ? 变色（SHOOT 时须指定颜色）
位置：0-based，从轨道左端起；SHOOT <pos> 表示插入后新球位于下标 pos。
```

**REVERSE**（消除输出同 SHOOT 的 ELIM/TRACK 结构）：

先处理左拼缝及其连锁，再处理仍幸存的右拼缝；两次检查是独立连锁，
各自从 round=1 计分。若第二拼缝已被第一条连锁消除，不重复处理。
例如 `GGRGRGRR` 反转 `[2,5]` 先消 `GGG` 再消 `RRR`，
轮次 `[1,1]`、得分 `30+30=60`，不是一次两轮连锁。


```text
REVERSE <i> <j>
[ELIM ... / TRACK ... 每轮消除各一条]
TRACK <轨道>                 无消除时输出这一条；有消除时最后一轮的 TRACK 已是终态
```

**QUIT**：仅输出 `QUIT_SCORE`（§3.3），无回显行，随后立即停止输入处理。

### 3.3 终局

进入 WIN / LOSE / QUIT 时**立即**输出：

```text
WIN SCORE=<score> MOVES=<moves>          轨道清空
LOSE SCORE=<score> MOVES=<moves>         队列耗尽且轨道非空，或步数达 LIMIT
QUIT_SCORE SCORE=<score> MOVES=<moves>   QUIT 指令
```

`MOVES` = 已执行的合法操作步数（UNDO 恢复为被撤销步的前值；HINT 不计）。

**终局后指令**（v1.3，装载即终局与操作后终局相同）：

- WIN/LOSE 的终局行只输出一次；之后仍接受 `HELP`、`UNDO`、`QUIT`。
- `HELP` 回显并输出帮助；`UNDO` 有记录时回退，无记录报 `ERROR 撤销栈为空`。
- 其他指令均回显原文后输出 `ERROR 终局后不接受指令`，不改变状态。
  此时 `HINT` 也必须回显（PLAYING 时才以结果行替代回显）。
- `QUIT` 在任何当前状态下输出一条 `QUIT_SCORE` 并立即结束输入处理，
  后续所有文本不解析、不回显、不执行；不会因后续 UNDO 再次进入游戏。
- 装载终局没有可撤销的初始化记录，但 HELP 仍可使用。

### 3.4 非法指令（不改变任何游戏状态、不计步数）

```text
<原指令回显行>
ERROR <原因>               原因短语固定（见下表）
```

原因码表（v1.1；driver 输出的固定短语，`test`/oracle 按字面比对）：

| 原因短语 | 触发场景 |
| --- | --- |
| `SHOOT 缺少位置参数` | `SHOOT` 后无参数 |
| `SHOOT 位置不是非负整数` | 位置含非数字 |
| `SHOOT 参数格式错误（<pos> 或 <pos> <大写字母>）` | 多余参数/颜色不是单个大写字母 |
| `REVERSE 需要 <i> <j> 两个参数` | 参数个数不对 |
| `REVERSE 参数不是非负整数` | i/j 含非数字 |
| `HELP 不接受参数` | `HELP` 带参数 |
| `未知指令或参数数量错误` | 无法识别的指令 |
| `发射位置越界` | `pos ∉ [0, n]` |
| `待发射队列为空` | 队列耗尽时 `SHOOT` |
| `变色球必须指定 COLORS 内的颜色` | 队首为 `?` 而未带颜色/颜色非法 |
| `仅变色球可指定颜色` | 普通球/炸弹携带颜色 |
| `反转区间越界` | 不满足 `0 ≤ i ≤ j < n` |
| `队列不足两球，无法交换` | `SWAP` 时队列 < 2 球 |
| `撤销栈为空` | 无可撤销操作 |
| `终局后不接受指令` | WIN/LOSE 后执行 UNDO/HELP 以外的指令 |

**非法后游戏继续**（下一行指令照常处理）。非法指令的零副作用是硬约束：
core 对变色球/颜色的校验先于出队，校验失败时队首球保留（阶段 3 修复）。

## 4. 胜负规则（D5）

| 终局 | 条件（按优先级） |
| --- | --- |
| WIN | 轨道清空（装载即清空亦 WIN） |
| LOSE | 队列耗尽**且**轨道非空；或步数达到 LIMIT 且轨道非空 |
| QUIT | QUIT 指令 |

每次消除/操作后重判；WIN 优先于 LOSE（LIMIT 最后一步恰好清空轨道判胜）。

## 5. 计分与提示（D5）

- 消除：`count × 10 × 2^(round-1)`（连锁每轮倍率翻倍：10 → 20 → 40 …）。
- **分数上限/饱和策略**：`kScoreCap = 2^53 − 1 = 9007199254740991`
  （JavaScript `Number.MAX_SAFE_INTEGER`）。每轮 `points` 与总分累加都
  饱和到该值（超过即取上限），保证深连锁下分数非负、单调不减，且 C++
  `int64` 与 JS `Number` 两端逐字节一致。34 轮深连锁（理论分
  687194767310）不受影响；60 轮等极端局面稳定饱和于上限。
- 撤销：分数与步数同步回滚到该步前值。
- HINT 最优 = 使插入后**立即消除的球数**最大的位置；等消除数取最左；无可消除位置返回 `-1`；队首为 `?` 返回 `-1`（定色自由度大，不提示）。炸弹每个插入位的首轮数均为 `min(3,n+1)`，因此同分最左位置为 `0`，包括端点与单球轨道。

## 6. 规模与确定性

- 初始输入：颜色 2~8 种；轨道 ≤ 10³ 球；队列 ≤ 2×10³ 球；UNDO 无上限（链栈）。
  这些是装载边界：游戏中插入后轨道可增长，不再以初始轨道上限拒绝发射。
- 头部不合法时 C++ 向 stderr 输出 `输入错误: <原因>` 并返回 1，不输出 READY；
  JS 解析返回 `{ok:false,error:<原因>}`。新增原因分别为
  `颜色数量必须为 2–8 种`、`初始轨道最多 1000 球，队列最多 2000 球`。
  颜色空串沿用原有缺失/空集合错误；先检查颜色数量，再检查长度，最后检查字符。
- **全程序无随机**：轨道、队列、变色球定色、消除顺序全部由输入决定。同输入必同输出（`test` 逐字节比对的基础）。
- 输出每行以 `\n` 结尾，行内以单个空格分隔 token。

## 7. 空行与结尾

- 输入头部后的空行忽略；`#` 起始的行视为注释忽略（样例可读性用）。
- 输入 EOF 视同终局未判（PLAYING 态直接结束）：输出 `QUIT_SCORE ...`（协议规定 EOF 需显式 QUIT，未给出者按退出计）。

## 8. CLI 渲染模式（阶段 3，不进入输出契约）

提交版只附源码。先在包含 `Makefile` 的根目录执行 `make` 生成 `zuma`
与 `test`，再执行本节中的 `./zuma` 命令。`make check` 会自动完成所需编译。

driver 有**纯协议**与**交互渲染**两种 stdout 形态，事件数据完全同源：

| 模式 | 判定 | 内容 |
| --- | --- | --- |
| 纯协议 | stdout 非终端（默认）；或 `--plain` | 即 §3 全部内容，逐字节可比对 |
| 交互渲染 | stdout 是终端（默认）；或 `--ui` | §3 协议行 + 以**两个空格**开头的提示行（`✦` 事件、`▸` 错误建议、`·` 状态摘要） |

- **颜色**：交互模式下球串按 COLORS 逐球上 ANSI 色（`*` 白字红底、`?` 亮洋红），
  轨道/队列/`ELIM` 的球串同样上色。默认仅在 stdout 是终端且处于交互模式时
  上色；`NO_COLOR`（存在且非空）关闭颜色；`TERM=dumb` 亦关闭；`--color`
  显式强制（优先于 NO_COLOR），`--no-color` 强制关闭。
- **契约保证**：交互提示行与颜色码只在交互模式出现；`test` 以 `--plain`
  + `NO_COLOR=1` 的子进程方式运行主程序（即使不重定向也保证纯文本），
  因此样例比对不受渲染影响。任何 `outputs/`/oracle 比对**只看纯协议模式**。
- `HELP` 的正文在两种模式下相同（交互模式仅给命令名列上色），属 §3.2 契约。
- 用法示例：

  ```sh
  ./zuma < inputs/case01.txt          # 纯协议（测试通道）
  ./zuma --ui < inputs/case01.txt     # 强制交互渲染（NO_COLOR=1 可关色）
  ./zuma --help                       # 命令行开关说明
  ```
