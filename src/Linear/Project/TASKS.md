## 一、项目决策（✅ 已确认 / ❓ 待确认）

### ✅ D1 · 用户交互形式（影响用户交互 20% 评分）

**选定 B：命令行 + ANSI 彩色终端渲染。** 仍是流式 stdin/stdout IO，`test` 程序可直接复用主程序比对输出；ANSI 颜色码输出需可通过开关关闭（`NO_COLOR` 环境变量或编译选项），保证样例比对时输出为纯文本。

### ✅ D2 · 轨道数据结构选型（影响数据结构 30% 评分）

**选定 A：双向链表（本项目自实现）。** 定位后插入/删除 O(1)，消除后两段拼接、连锁沿拼缝向两侧扩展最自然。Baseline 无双向链表可复用，此为项目的核心自实现数据结构。

### ✅ D3 · 待发射队列与撤销栈选型

**队列选 C：本项目自实现**（语义参照 Baseline `CircularQueue`，固定容量 + 环形缓冲）。
**撤销选 A：命令模式。** 撤销栈记录"操作参数 + 被消除彩球序列 + 消除前位置"，撤销时逆序恢复；栈本体使用项目内 `LinkedStack<T>`（见 D6 最终方案）。

### ✅ D4 · 小道具功能清单（功能评分的加分项）

**选定全部五项**：炸弹球、变色球、交换头两球、提示、倒退。实现顺序：**先完成基础功能（必做七项）并测试，再补充道具**，每个道具 = 一个 core 层函数 + 一条指令 + 至少一个测试样例。

### ❓→✅ D5 · 输入输出与规则细节约定（已按建议方案确认，2026-10-20）

**以下方案已确认采纳：**

| 待定项 | 建议值 |
| --- | --- |
| 颜色符号 | 普通球 `R G B Y`（≤8 种，大写单字母）；特殊球：`*` 炸弹、`?` 变色（可出现在待发射队列中） |
| 指令语法 | 头部三行 `COLORS ...` / `TRACK ...` / `QUEUE ...`（可选第四行 `LIMIT n`），之后每行一条：`SHOOT <pos>`、`SHOOT <pos> <color>`（变色球定色）、`UNDO`、`SWAP`、`HINT`、`REVERSE <i> <j>`、`QUIT` |
| 位置编号 | 0-based 从轨道左端起；`SHOOT p` 表示插入后新球位于下标 p（即插到当前下标 p 之前），p ∈ [0, n]，p = n 为尾插；`REVERSE i j` 为闭区间 [i, j] |
| 胜负规则 | 胜 = 轨道清空；负 = 队列耗尽且轨道非空，或操作数超过 `LIMIT`（未设 LIMIT 则不限）；`QUIT` = 按当前状态输出未完成 |
| 随机性 | 无。轨道、队列、全部序列均由输入文件给定，保证 `test` 可比对 |
| 规模上限 | 颜色 ≤ 8 种、初始轨道 ≤ 10³、队列 ≤ 10³、撤销无上限（链栈） |
| 炸弹语义 | 插入后消除以炸弹为中心的连续 3 球（不足 3 时消到轨道边界，至少消炸弹自身，无视颜色），消除后照常检查拼缝连锁 |
| 计分 | 消除 10 分/球，连锁每追加一轮 ×2（10→20→40…）；每轮与总分饱和于 2^53−1（PROTOCOL §5）；撤销时分数同步回滚 |

确认结果：**已按建议方案全项采纳**（2026-10-20，用户确认"按建议来"）
